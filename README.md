# Прогноз денежных потоков

Локальный демонстрационный прототип для малого бизнеса: помогает анализировать банковскую выписку, группировать операции, учитывать известные будущие платежи и оценивать изменение остатка. Все пользовательские данные обрабатываются в текущем приложении и не отправляются во внешние сервисы.

> CSV в `data/demo/` и все расчёты на их основе синтетические. Они не описывают реальную компанию, налоговые обязательства или точность на реальных данных.

## Возможности

- Загрузка CSV/XLSX, автоматическое сопоставление русских и английских заголовков и ручная настройка колонок.
- Проверка строк, нормализация поступлений в положительные суммы и списаний в отрицательные; отчет о некорректных и повторных строках.
- Восстановление начального остатка дня как конечный остаток минус сумма всех подписанных операций этого дня; проверка согласованности соседних дней.
- Обособленный анализ каждого счета: автоматического сложения остатков нескольких счетов нет.
- Правила категоризации и опциональный TF-IDF/Logistic Regression классификатор, который обучается только на явно размеченных операциях.
- Поиск регулярных платежей по контрагенту, назначению, категории, сумме и интервалам. Для подтверждения серии требуется не менее трех наблюдений; пользователь должен отдельно подтвердить прогноз.
- Импорт, ручное создание, редактирование и смена статуса будущих событий. Налоговые данные не рассчитываются и не загружаются автоматически.
- 30/60/90-дневный прогноз потоков и остатка; известные события добавляются отдельным слоем и не учитываются повторно с подтвержденной регулярной серией.
- Временная walk-forward-проверка базового сезонного прогноза и ML-модели, метрики MAE/RMSE/WAPE.
- Детерминированная оценка нарушения минимального резерва и сценарная вероятность на блочном bootstrap ошибок исторического прогноза, когда доступно не менее 30 ошибок.

## Архитектура

`app.py` содержит только интерфейс. `src/data/` отвечает за загрузку и нормализацию; `src/categorization/` — классификацию; `src/recurring/` и `src/future_events/` — будущие потоки; `src/forecasting/` — прогноз, признаки и оценку; `src/risk/` — оценку ликвидности. Конфигурация находится в `config/`.

## Установка и запуск

Требуется Python 3.11 или новее (зависимости используют актуальные версии библиотек).

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

В Linux/macOS активируйте окружение командой `source .venv/bin/activate`.
Тесты: `pytest -q`.

## Выписка

Обязательные поля: дата и сумма. Поддерживаемые поля: направление, контрагент, ИНН, назначение, остаток на конец дня, счет. Значения суммы могут иметь десятичную запятую. Если направление распознано, оно определяет знак модуля суммы; таким образом значение `-100` с направлением «поступление» нормализуется в `+100`, а повторное изменение знака не производится. Без направления исходный знак сохраняется.

Колонки даты/суммы можно сопоставить в интерфейсе. Если у нескольких счетов нет идентификатора, операции относятся к одному счету «Основной счёт»; перед анализом такого файла проверьте структуру.

Вход событий: столбцы `date`, `amount`, `direction` (поступление/списание), необязательно `category`, `status`, `source`, `description`, `account`. Сумма у события задается модулем, знак формируется из направления. Статусы: ожидается, подтверждено, исполнено, отменено.

## Прогноз и проверка качества

Данные сначала агрегируются по календарным дням, включая дни с нулевыми потоками. Базовая модель использует историческую медиану для того же дня недели либо последних 28 дней. ML-вариант — HistGradientBoostingRegressor с лагами, скользящими средними и календарными признаками; поступления и расходы прогнозируются раздельно. ML требует достаточной истории. При выборе `auto` модель выбирается по временному walk-forward-сравнению, а при отсутствии достаточной проверки остается базовый вариант.

На каждой точке отсечения обучение использует только прошлые даты. В отчёте доступны MAE, RMSE и WAPE для чистого потока. Метрики не являются гарантией качества на будущем периоде. Остаток прогнозируется накоплением прогнозного чистого потока от последнего известного остатка. Если конечного остатка в выписке нет, его нужно указать вручную.

## Риск кассового разрыва

Детерминированный сценарий отмечает первую дату, когда прогноз остатка ниже заданного резерва, и максимальный дефицит. Если имеется не менее 30 walk-forward-ошибок, создаются воспроизводимые сценарии блочного bootstrap с блоком 7 дней; вероятность — доля траекторий, пересекших порог. Сценарии сохраняют локальную временную зависимость внутри блока. При недостатке ошибок приложение не показывает выдуманную вероятность.

## Ограничения и дальнейшая интеграция

- Синтетическая демонстрация не заменяет проверку на выписках пользователя.
- Периодичность ежемесячных/ежеквартальных серий приближенно оценивается интервалами в 30/91 день.
- Валютная конвертация, взаимозачеты между счетами и идентификация таких переводов требуют проверки.
- Вероятность отражает только исторические ошибки прогноза, а не все возможные экономические шоки.
- Историческая проверка сопоставляет потоки и не использует случайное разбиение временного ряда.
- Для интеграции внешнего банка, бухгалтерской системы или налогового календаря нужен отдельный документированный адаптер, пользовательское разрешение и тестовые данные. Реальных интеграций в прототипе нет.
